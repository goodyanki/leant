# M0 性能基线报告：`Std.Http` vs `Gin` vs `Rust (Hyper) + Lean 4 FFI`

- **测试日期**：2026-11-22
- **环境**：Linux x86_64（2 vCPU，`ulimit -n 1024`）
- **工具链**：Lean `v4.36.0` (Release)、Go `1.26.11` + Gin `v1.12.0` (`gin.ReleaseMode` + `gin.New()`)、Rust `1.100.0` (`tokio 1.54` + `hyper 1.12`)、`wrk 4.1.0`
- **方法**：每个场景预热 2s 后压测 5s，采集 RPS、p50/p99 延迟、错误数与进程 RSS。

## 对比结果

| 场景 | Gin (`ReleaseMode`) | 裸 `Std.Http` | `Std.Http / Gin` | **Rust (`hyper`) + Lean 4 FFI** | 混合 / Gin |
| --- | ---: | ---: | ---: | ---: | ---: |
| `GET /` `c=1` | 8,691 RPS (p99 0.67ms) | 894 RPS (p99 1.80ms) | 10.3% | **14,191 RPS** (p99 0.81ms) | **1.63x** |
| `GET /` `c=16` | 31,917 RPS (p99 7.57ms) | 2,728 RPS (p99 9.20ms) | **8.5%** | **86,821 RPS** (p99 4.63ms) | **2.72x** |
| `GET /` `c=64` | 39,812 RPS (p99 8.65ms) | 3,193 RPS (p99 29.81ms) | **8.0%** | **92,349 RPS** (p99 4.33ms) | **2.32x** |
| `GET /` `c=256` | 44,728 RPS (p99 20.30ms) | 3,122 RPS (p99 762.00ms) | **7.0%** | **93,173 RPS** (p99 7.23ms) | **2.08x** |
| `GET /` `c=512` | 47,992 RPS (p99 35.10ms, 0 err) | 2,934 RPS (p99 1.33s, **181 timeout**) | **6.1%** | **94,823 RPS** (p99 13.71ms, 0 err) | **1.98x** |
| `GET /json` `c=64` | 38,293 RPS (p99 10.20ms) | 2,993 RPS (p99 97.25ms) | **7.8%** | **101,695 RPS** (p99 4.35ms) | **2.66x** |
| 短连接 `c=32` | 13,832 RPS (p99 6.62ms) | 1,586 RPS (p99 27.73ms) | 11.5% | **19,717 RPS** (p99 4.59ms) | **1.43x** |
| 压测峰值 RSS | 28.9 MB | 15.7 MB | — | **14.0 MB** | 0.48x |

> 补充验证：关闭 `Std.Http` 的 `generateDate` 和 `serverName` 后，`c=64` 为 3,221 RPS，`c=512` 为 2,711 RPS 且仍有 221 次超时，瓶颈位于 `Std.Http.Server.Connection` 的每请求 `Selectable` 数组/任务调度与单事件循环模型。

## 决策点 D0 结论

裸 `Std.Http` 同时触发了 **< Gin 10%**（并发下 6.1%–8.5%）与 **高并发超时/尾延迟失控** 两条红线。
因此启用备选方案（见 [ADR-001](../../docs/adr/001-rust-hyper-transport.md)）：`Leant.Transport` 默认采用 **Rust (`tokio` + `hyper` 1.x) HTTP 层 + C ABI shim**，Lean 4 专注路由、中间件、类型安全绑定、ORM 与可证明授权层。
